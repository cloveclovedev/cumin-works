利用制限

HostのClaude Codeのアカウントの利用制限を、cuminがどう守るかを決める。利用制限は、Operatorが自分の作業に使う分と同じアカウントのものである。そこで、週間制限は週を通して均等に使い、5時間制限は時間帯ごとにOperatorの分を残す。1回の実行の時間の上限はAgentのCWK-AGENT-015で、ツール動作確認で止めることはCWK-AGENT-018.3で決める。

全体像

利用制限で変わるのは、Issueの状態ではなく、cumin自身の状態である。状態はHostの手元にあり、GitHubにはない。cumin 1つにつき1つで、すべてのリポジトリに効く。

Agent起動を止めている間も、Agentを起動しないアクション（ラベルの付け替え、コメント、通知、マージ、Issueを閉じること）は続ける。

要件

使用率を読む

CWK-LIMIT-001 Agent起動の前に決める

cuminは、Agentを起動する前に、5時間制限と週間制限の使用率から、起動してよいかを決める。着手、続きのAgent起動、やり直しのどれでも同じである。

  • 検証: test 使用率が上限以上のとき、計画、実装、レビュー、チェックの修正、受け入れ確認、やり直しの、どのAgent起動も起きない

CWK-LIMIT-002 使用率の読み方

cuminは、使用率をAgentのCLIから読む。同じアカウントはcuminの外でも使われるので、手元の使用率が古ければ、起動の前に読み直す。直前の実行で読んだばかりの使用率は、そのまま使う。読んだ使用率は、制限ごとのリセット時刻と読んだ時刻とともに、Hostの手元に残す。

  • 検証: test 手元の使用率が古いときは、起動の前に読み直す。読んだばかりなら、読み直さない

CWK-LIMIT-003 読めないとき

Agent起動の前に使用率を読めなければ、cuminは起動せずに、通知する。次の定期確認で読み直す。

  • 検証: test 使用率を読めないと、Agent起動が起きず、通知が1回届く

上限

CWK-LIMIT-004 5時間制限の上限

5時間制限の上限は、今の時刻の時間帯のしきい値である。時間帯ごとのしきい値はquota.five_hour.bandsで、どの時間帯にも入らない時刻のしきい値はquota.five_hour.threshold（初期値は85%）で決める。Operatorが使わない時間帯は、しきい値を高くできる。

  • 時間帯はfromを含み、toを含まない。時刻はHostのローカルの時刻である。

  • toがfromより前なら、日付をまたぐ

  • 同じ時刻を2つの時間帯に入れられない。入れると、両方の位置を示す設定の誤りになる。

  • 検証: test 同じ使用率で、しきい値の低い時間帯では止まり、高い時間帯では止まらない

CWK-LIMIT-005 週間制限の上限

週間制限の上限は、ペースの上限 = 目標 × min(1, (経過時間 + 前倒し) ÷ 7日)である。経過時間は、週間制限のリセット時刻の7日前から数える。目標はquota.weekly.target（初期値は85%）、前倒しはquota.weekly.lead（初期値は1日）で決める。リセット時刻は使用率とともに読み、設定には持たない。

  • 検証: test 使用率が変わらないまま、週の始めは止まり、ペースの上限が使用率を上回ったあとの定期確認で再開する。上限は目標を超えない

CWK-LIMIT-006 5時間制限を使い切る許可

Operatorがcumin quota allowを実行すると、その5時間制限がリセットされるまで、5時間制限のしきい値を100%とする。週間制限の上限は、この許可でも、ほかのどの方法でも上がらない。週間制限を使い切ると、Operatorが何日も使えなくなるからである。

  • 検証: test 5時間制限で止まっているとき、許可すると再開する
  • 検証: test 週間制限で止まっているときは、許可しても再開しない

止めることと再開すること

CWK-LIMIT-007 Agent起動を止める

使用率が5時間制限か週間制限の上限以上の間、cuminはすべてのリポジトリでAgent起動を止める。動いているAgentは止めない。止めたAgent起動のための状態ラベルの付け替えもせず、Issueは今の状態のまま残る。止めたAgent起動は、やり直しの回数に含めない。

  • 検証: test 上限の間に必須チェックが完了しても、実装Issueはcumin/status/checkingのまま残り、上限のあとの定期確認でレビューが1回だけ始まる
  • 検証: test 上限の間も、承認されたPull Requestはマージされる

CWK-LIMIT-008 止めたことを知らせる

cuminは、Agent起動を止めたときに、止めた原因の制限を書いて通知する。再開するまで、同じ制限について通知するのは1回だけである。

  • 検証: test 上限のまま定期確認を3回行っても、通知は1回だけである

CWK-LIMIT-009 再開する

止めている間、cuminは、手元に残した使用率から次に試す時刻を決め、その時刻までは使用率を読むためだけの実行をしない。その時刻を過ぎ、両方の制限が上限未満なら、Agent起動を再開する。

  • 5時間制限で止めているとき: 5時間制限のリセット時刻と、しきい値が残した使用率を上回る時間帯の始まりの、早いほう

  • 週間制限で止めているとき: ペースの上限が残した使用率を上回る時刻と、週間制限のリセット時刻の、早いほう

  • 両方で止めているとき: 両方の時刻の、遅いほう

  • 検証: test 5時間制限のリセット時刻を過ぎると、人の操作なしに再開する

  • 検証: test 次に試す時刻の前には、使用率を読むための実行が起きない

受け入れテスト

# 場面 期待する結果
1 5時間制限の使用率が、今の時間帯のしきい値に達する Agent起動が止まり、通知が1回届く（CWK-LIMIT-007、CWK-LIMIT-008）。動いているAgentは最後まで動く。リセットのあとか、しきい値の高い時間帯に入ると、再開する（CWK-LIMIT-009）
2 5時間制限で止まっているときに、Operatorがcumin quota allowを実行する 再開する（CWK-LIMIT-006）
3 週間制限で止まっているときに、Operatorがcumin quota allowを実行する 再開しない（CWK-LIMIT-006）
4 上限の間に、ReviewerがREQUEST_CHANGESを出して終わる Implementerは起動されず、実装Issueはcumin/status/reviewingのまま残る。上限のあとの定期確認で、指摘の修正が1回だけ始まる（CWK-LIMIT-007）
5 Agent起動の前に、使用率を読めない 起動せずに、通知が1回届く（CWK-LIMIT-003）
