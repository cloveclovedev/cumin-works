# 利用制限

Host の Claude Code のアカウントの利用制限を、cumin がどう守るかを決める。利用制限は、Operator が自分の作業に使う分と同じアカウントのものである。そこで、週間制限は週を通して均等に使い、5時間制限は時間帯ごとに Operator の分を残す。1回の実行の時間の上限は [Agent](../agent/index.md) の `CWK-AGENT-015` で、ツール動作確認で止めることは `CWK-AGENT-018.3` で決める。

## 全体像

利用制限で変わるのは、Issue の状態ではなく、cumin 自身の状態である。状態は Host の手元にあり、GitHub にはない。cumin 1つにつき1つで、すべてのリポジトリに効く。

![利用制限の全体像](overview.svg)

図の元ファイル: [overview.puml](overview.puml)

Agent起動を止めている間も、Agent を起動しないアクション (ラベルの付け替え、コメント、通知、マージ、Issue を閉じること) は続ける。

## 要件

### 使用率を読む

#### `CWK-LIMIT-001` Agent起動の前に決める

cumin は、Agent を起動する前に、5時間制限と週間制限の使用率から、起動してよいかを決める。着手、続きの Agent起動、やり直しのどれでも同じである。

- 検証: `test` 使用率が上限以上のとき、計画、実装、レビュー、チェックの修正、受け入れ確認、やり直しの、どの Agent起動も起きない

---

#### `CWK-LIMIT-002` 使用率の読み方

cumin は、使用率を Agent の CLI から読む。同じアカウントは cumin の外でも使われるので、手元の使用率が古ければ、起動の前に読み直す。直前の実行で読んだばかりの使用率は、そのまま使う。読んだ使用率は、制限ごとのリセット時刻と読んだ時刻とともに、Host の手元に残す。

- 検証: `test` 手元の使用率が古いときは、起動の前に読み直す。読んだばかりなら、読み直さない

---

#### `CWK-LIMIT-003` 読めないとき

Agent起動の前に使用率を読めなければ、cumin は起動せずに、通知する。次の定期確認で読み直す。

- 検証: `test` 使用率を読めないと、Agent起動が起きず、通知が1回届く

---

### 上限

#### `CWK-LIMIT-004` 5時間制限の上限

5時間制限の上限は、今の時刻の時間帯のしきい値である。時間帯ごとのしきい値は `quota.five_hour.bands` で、どの時間帯にも入らない時刻のしきい値は `quota.five_hour.threshold` (初期値は85%) で決める。Operator が使わない時間帯は、しきい値を高くできる。

- 時間帯は `from` を含み、`to` を含まない。時刻は Host のローカルの時刻である。
- `to` が `from` より前なら、日付をまたぐ。
- 同じ時刻を2つの時間帯に入れられない。入れると、両方の位置を示す設定の誤りになる。

- 検証: `test` 同じ使用率で、しきい値の低い時間帯では止まり、高い時間帯では止まらない

---

#### `CWK-LIMIT-005` 週間制限の上限

週間制限の上限は、ペースの上限 = 目標 × min(1, (経過時間 + 前倒し) ÷ 7日) である。経過時間は、週間制限のリセット時刻の7日前から数える。目標は `quota.weekly.target` (初期値は85%)、前倒しは `quota.weekly.lead` (初期値は1日) で決める。リセット時刻は使用率とともに読み、設定には持たない。

- 検証: `test` 使用率が変わらないまま、週の始めは止まり、ペースの上限が使用率を上回ったあとの定期確認で再開する。上限は目標を超えない

---

#### `CWK-LIMIT-006` 5時間制限を使い切る許可

Operator が `cumin quota allow` を実行すると、その5時間制限がリセットされるまで、5時間制限のしきい値を100%とする。週間制限の上限は、この許可でも、ほかのどの方法でも上がらない。週間制限を使い切ると、Operator が何日も使えなくなるからである。

- 検証: `test` 5時間制限で止まっているとき、許可すると再開する
- 検証: `test` 週間制限で止まっているときは、許可しても再開しない

---

### 止めることと再開すること

#### `CWK-LIMIT-007` Agent起動を止める

使用率が5時間制限か週間制限の上限以上の間、cumin はすべてのリポジトリで Agent起動を止める。動いている Agent は止めない。止めた Agent起動のための状態ラベルの付け替えもせず、Issue は今の状態のまま残る。止めた Agent起動は、やり直しの回数に含めない。

- 検証: `test` 上限の間に必須チェックが完了しても、実装Issueは `cumin/status/checking` のまま残り、上限のあとの定期確認でレビューが1回だけ始まる
- 検証: `test` 上限の間も、承認された Pull Request はマージされる

---

#### `CWK-LIMIT-008` 止めたことを知らせる

cumin は、Agent起動を止めたときに、止めた原因の制限を書いて通知する。再開するまで、同じ制限について通知するのは1回だけである。

- 検証: `test` 上限のまま定期確認を3回行っても、通知は1回だけである

---

#### `CWK-LIMIT-009` 再開する

止めている間、cumin は、手元に残した使用率から次に試す時刻を決め、その時刻までは使用率を読むためだけの実行をしない。その時刻を過ぎ、両方の制限が上限未満なら、Agent起動を再開する。

- 5時間制限で止めているとき: 5時間制限のリセット時刻と、しきい値が残した使用率を上回る時間帯の始まりの、早いほう
- 週間制限で止めているとき: ペースの上限が残した使用率を上回る時刻と、週間制限のリセット時刻の、早いほう
- 両方で止めているとき: 両方の時刻の、遅いほう

- 検証: `test` 5時間制限のリセット時刻を過ぎると、人の操作なしに再開する
- 検証: `test` 次に試す時刻の前には、使用率を読むための実行が起きない

---

### 起動の前の1つの確認

#### `CWK-LIMIT-010` すべての Agent起動の前の確認

cumin は、どの Agent起動の前にも、同じ1つの確認を行う。確認するのは、利用制限 (`CWK-LIMIT-007`)、そのリポジトリのツール動作確認 (`CWK-AGENT-018.3`)、止める予約 (`CWK-HOST-007`) である。新しい種類の Agent起動を足しても、この確認を飛ばせない。

- 検証: `inspection` Agent を起動するコードの呼び出し元が1つだけで、その前に確認があることを、テストで確かめる

---

## 受け入れテスト

| # | 場面 | 期待する結果 |
|---|---|---|
| 1 | 5時間制限の使用率が、今の時間帯のしきい値に達する | Agent起動が止まり、通知が1回届く (`CWK-LIMIT-007`、`CWK-LIMIT-008`)。動いている Agent は最後まで動く。リセットのあとか、しきい値の高い時間帯に入ると、再開する (`CWK-LIMIT-009`) |
| 2 | 5時間制限で止まっているときに、Operator が `cumin quota allow` を実行する | 再開する (`CWK-LIMIT-006`) |
| 3 | 週間制限で止まっているときに、Operator が `cumin quota allow` を実行する | 再開しない (`CWK-LIMIT-006`) |
| 4 | 上限の間に、Reviewer が `REQUEST_CHANGES` を出して終わる | Implementer は起動されず、実装Issueは `cumin/status/reviewing` のまま残る。上限のあとの定期確認で、指摘の修正が1回だけ始まる (`CWK-LIMIT-007`) |
| 5 | Agent起動の前に、使用率を読めない | 起動せずに、通知が1回届く (`CWK-LIMIT-003`) |
